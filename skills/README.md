# Unified skills library

One canonical, browsable home for every Claude Code **skill**, **slash command**,
and **agent** harvested from across the machine's projects (`C:\code\*`), the
global `~/.claude` config, and a set of **borrowed open-source collections** we
vendor as we go (see [Vendored external skills](#vendored-external-skills-borrowed-with-thanks)).
Everything here is **copied, never moved** — upstream projects are untouched, and
every borrowed skill keeps its origin, author, and license recorded.

## Why two trees

Claude Code auto-discovers skills only as *flat* `<name>/SKILL.md` folders under a
`skills/` root; it does **not** recurse into category sub-folders. So the library
keeps two trees:

- **`catalog/`** — **harvested** skills, organized by category. Browse this.
  Regenerated (wiped + rebuilt) from upstream by `harvest.py`.
- **`authored/`** — **hand-written** skills original to this library (e.g. the
  PowerShell set). Committed source; `harvest.py` never touches it.
- **`loadable/`** — a flat mirror Claude can actually load, generated by `sync.py`
  by merging `catalog/` + `authored/`. Gitignored (pure derived output).

## Workflow

```bash
python harvest.py                 # upstream  -> catalog/   (+ MANIFEST.json)
python sync.py --target local     # catalog/  -> loadable/             (default)
python sync.py --target plugin    # catalog/  -> <repo>/plugin/  (committed plugin bundle)
python sync.py --target project   # catalog/  -> <repo>/.claude/       (load here)
python sync.py --target global    # catalog/  -> ~/.claude/   (load everywhere)
```

The `plugin` target is the flat, **committed** bundle the Claude Code plugin
(`.claude-plugin/plugin.json`) points at (`plugin/{skills,commands,agents}/`).
Re-run it after editing skills, then commit `plugin/`. `sync.py` skips (with a
loud warning) any manifest source absent from the checkout, so a partial clone
still builds.

`harvest.py` is idempotent: it wipes and rebuilds `catalog/` from the explicit
list in `sources.toml`. `sync.py --target local` wipes and rebuilds `loadable/`;
`project`/`global` overwrite per item so any unrelated skills already living
there are left alone.

## Provenance & dedup

`MANIFEST.json` records every item's upstream origin path and a sha256 of its
defining file. To add or refresh an asset, edit `sources.toml` (the single,
explicit work-list) and re-run `harvest.py`.

Duplicates were collapsed to one canonical copy:
- The 4 `llm-station-*` skills exist in three identical upstream copies
  (`.claude`, `.agents`, `src/ralph`) plus global — only the project `.claude`
  copy is harvested.
- `build-*` commands are taken from chukonu (identical to the global copies).
- `debug-windows-msvc` / `debug-linux-lldb` live only in global `~/.claude`.

`harvest.py` asserts skill names are globally unique and fails loudly on any
collision rather than silently overwriting.
