# Review of PRs 15 through 18

Reviewed the source branches, original issues and posted review discussion on
2026-09-26. The four PRs are a stack: 15 targets main, 16 targets 15, 17 targets
16, and 18 targets 17. Their initial heads were 7faea45, f5386d7, c451229 and
484bd12 respectively. No PR had check results. GitHub Actions was disabled at
repository level, and the Python workflow also excluded PRs targeting branches
other than main.

The original combined stack passed 882 tests with one skipped on this machine.
That result did not validate the new PowerShell, plugin packaging or old-SQLite
paths. The prose gate failed with 90 findings, including pre-existing archived
skills and new README text. The plugin mirror did regenerate without changes;
the suspicion that it was still stale was disproved.

## PR 15: service port

Changing the shared service default to 8010 is consistent with the existing
POSIX service script. Devin's follow-up commit 7faea45 contains
`if (Test-Dashboard -and Test-Mcp)`. PowerShell treats the remainder as function
arguments, not a boolean expression. An actual PowerShell reproduction with
Dashboard=true and MCP=false still entered the healthy branch.

The proposed fallback also launches a second MCP instance while the old process
retains the dashboard, splitting the service across processes. The follow-up
commit was never propagated to the three higher branches. Its advertised
PowerShell fix also moved 20 skill/command/agent source paths without updating
the manifest, which belonged to the cleanup PR. PR 15 alone therefore had stale
manifest paths and an inconsistent generated bundle.

Repair: evaluate both health functions separately, refuse partial service
health, wait for both endpoints, reject unrelated HTTP statuses, quote the repo
path for Windows process launch, and document uninstall/stop-old/install-new.
Added executable PowerShell regression tests and a Windows 5.1/7 CI job.
Restored the accidentally moved sources on PR 15 and repaired its existing prose
and plugin-mirror baseline. PR 16 then applies its intentional removals. Its
history-only reconciliation merge retains the tested cleanup tree while taking
the repaired PR 15 as an ancestor.

## PR 16: public bundle

The initial cleanup correctly retained sidelined sources and regenerated the
bundle. It did not finish its stated scope: `debug-linux-lldb` and
`debug-windows-msvc` still instructed users to build/debug a specific chukonu
checkout. Skills documentation still described removed assets as active.

Repair: sideline both remaining project drivers in the catalog, manifest and
harvest source map; regenerate the bundle; update counts to 109 skills, one
command and four agents. All 80 harvested active skills are external sources;
29 are authored. Keep `clean-test-data`, whose instructions are project-generic.

Added a byte-for-byte regeneration test that also asserts excluded assets stay
excluded. The CI mirror gate now detects untracked generated files as well as
tracked diffs; `git diff` alone misses newly generated files. Python CI now
matches all PR base branches. Normalized flagged authored prose without changing
vendored source or weakening the prose gate.

## PR 17: Codex integration

The PR conflates the `.codex-plugin` manifest format with the root Agent Plugins
format. In the installed Codex 0.155.1 loader, the ordinary plugin MCP parser
normalizes `cwd` but does not expand `${PLUGIN_ROOT}` in arguments. Adding the
Agent Plugins schema URI inside that MCP file does not select the other parser.
See the [versioned parser source](https://github.com/openai/codex/blob/rust-v0.155.1/codex-rs/codex-mcp/src/plugin_config.rs)
and [versioned loader source](https://github.com/openai/codex/blob/rust-v0.155.1/codex-rs/core-plugins/src/loader.rs).

The project-map manifest's missing `mcpServers` field also permits fallback to
its Claude `.mcp.json`, contrary to the claim that it is skills-only. Finally,
`cd project; codex mcp add ...` does not make a user-scoped registration
project-scoped.

Repair: launch `uv run devtools-mcp` with plugin-relative `cwd: "."` and no
placeholders; explicitly set project-map's `mcpServers` to an empty object;
document a target project's `.codex/config.toml` with an explicit index root.
Tests launch the configured command and discover real MCP tools, then verify
project-map indexes the configured project from an unrelated process cwd.
These tests do not install into or alter the user's Codex configuration.

## PR 18: DBOS and SQLite

The minimum SQLite guard is useful. Calling `pytest.skip` from the global
autouse fixture skips every test on old SQLite, including tests unrelated to
recipes. It converts broken infrastructure into an apparently successful suite
with no coverage. Installing `pysqlite3-binary` alone also does not replace the
active stdlib `sqlite3` module, so the suggested remedy is incomplete.

Repair: keep the early production guard and accurate upgrade guidance; make the
autouse fixture return an unavailability reason; only explicit `dbos_runtime`
users skip. Preserve and restore the prior DBOS test path, and isolate Station
credentials in tests. Added boundary-version tests, early-construction failure,
server degradation and a subprocess test proving unrelated tests still execute
under a simulated old SQLite version.

## Integration and verification limits

Repairs propagate upward with ordinary merges, preserving the original PR heads
as ancestors. No rebase, force push, merge to main or changes to the user's dirty
checkout are required. The earlier Station-core implementation remains on its
separate branch and is not silently folded into these PRs.

PowerShell behavior was exercised with the official PowerShell 7.6.6 ARM64
runtime on macOS, with Windows process/HTTP calls mocked. Actual Windows startup
shortcuts and Windows PowerShell 5.1 require the configured Windows CI job or a
Windows machine. Old-SQLite tests simulate the compatibility condition; the host
SQLite library itself is current. The real Codex plugin cache was not modified.

The simulated old-SQLite selection passed 44 tests and skipped only the 11
explicit durable-workflow tests. The focused SQLite/recipe/compatibility tests
passed 38 cases with normal SQLite; the Codex packaging tests passed three.

The final combined Python suite passed 891 tests with one skipped. Configured
Python CI checks (pytest, source lint, prose, plugin regeneration) passed locally.
PowerShell tests passed, including connection failures whose exception has no
Response property. Formatting checks passed on changed Python files. A broader
mypy run still reports 24 pre-existing errors in 12 files; all 12 files were
verified byte-identical to the original PR stack. This review does not claim
that repository-wide type checking is clean.
